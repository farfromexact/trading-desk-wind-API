# Wind 多品种实时机会工作台

本机 Wind 行情驱动的中文交易看板：15分钟识别环境、5分钟确认机会、实时价格预警。包含顺势突破回踩和区间假突破反转，输出参考触发价、结构失效价、目标与价格空间盈亏比。

## 跨平台维护与接手

**Windows 和 macOS 共用这个仓库、同一套业务代码。** 两个平台分别安装依赖和官方 Wind SDK，使用各自启动器；不复制 `.venv`、数据库或登录配置。

| 平台 | 安装/更新依赖 | 启动 | 停止 | 当前验证状态 |
| --- | --- | --- | --- | --- |
| Windows | `install.ps1` | `Start Dashboard.cmd` / `start.ps1` | `Stop Dashboard.cmd` / `stop.ps1` | 有原版实测记录；安装器及采集修复待 Windows 复验 |
| macOS | `install-mac.command` | `Start Dashboard Mac.command` | 启动终端按 Control+C | 11月12日夜盘15分钟：0重连，AG/AU无整组归零；SC期权已到期，日盘/全天待验 |

**Windows 接手本次更新：先读 [跨平台维护说明](docs/CROSS_PLATFORM.md)。** 确保 Mac 的改动已推送后再拉取，停止旧服务、重跑安装器、验证 Wind 连接和测试，再启动。Codex 会从根目录 [AGENTS.md](AGENTS.md) 读取平台约定、交接状态和验证要求。

拉取业务代码后通常需要重启；前端修改需要重新构建；依赖变更需要重跑对应安装器。不要建立两个仓库或长期 Windows/Mac 分支。Git 仅同步源码、依赖清单、共用配置和文档，不同步本机行情数据。

## Windows 日常启动

1. 在这台电脑启动并登录 Wind 金融终端。
2. 双击本目录 **Start Dashboard.cmd**，浏览器打开 **http://127.0.0.1:8765**。
3. 等待对应品种历史加载完成；开市且数据完整时卡片显示“实时”，休息时显示“午休”“小节休息”或“已收盘”。点击右上角“启用声音”；浏览器每次重新打开都需要一次用户点击。
4. 结束使用时双击 **Stop Dashboard.cmd**。只关闭网页不会停止后台采集。

程序只监听本机回环地址，只使用行情查询与订阅接口，不包含委托、撤单或账户交易功能。也可在 PowerShell 中运行：

```powershell
.\start.ps1
.\stop.ps1
```

如 PowerShell 阻止脚本，使用 CMD 启动器；其中执行策略只作用于该进程，不修改系统策略。

## 怎么看提示

| 状态 | 含义 |
| --- | --- |
| 关注中 | 接近区域或已有结构候选，仍缺收盘确认，默认静默 |
| 收盘确认 | 规则满足且 T1 价格空间达到默认1.5R；新实时确认响一次 |
| 已触价 | 最新成交价达到参考触发价，不代表实际成交 |
| 空间不足 | 结构满足但目标空间不足，保留信息且静默 |
| 已失效 / 已过期 | 失效价被触及、环境改变、跟随不足或超出等待期限 |
| 先后不确定 | 历史单根K线覆盖触发和失效价格，不能推定先后、成交或收益 |

单击机会卡定位图表并查看依据。红色为上涨/做多，绿色为下跌/做空。三个周期均显示已确认的5分钟结构：1/15分钟标注加“5m”前缀，15分钟把同根K线同侧的标注合并。1分钟位置对应来源5分钟K线的时间标签，并不声称该分钟独立形成同样结构。

金色边框K线是**盘中预览**，随最新报价更新；“未收盘”与“待核对”均不参与正式信号计算。预览使用Wind盘中分钟快照校准，再结合已接收报价更新，最终开高低收仍以完整原生分钟线为准。刚跨入新周期、尚无Wind快照时标为“局部报价”，此时开高低价可能不完整。“回到最新”可恢复当前行情位置；浏览历史时不会被实时更新强制拉回。

每日启动将 Wind 主力映射到真实月份合约，按品种交易日固定。商品在夜盘开始进入下一交易日，跨午夜不会重置；夜盘开始采用当时已知最近交易日的 Wind 主力映射。用“切换合约”输入同品种月份代码，例如 IM2611.CFE、AU2702.SHF、SC2701.INE、T2703.CFE。手动选择跨日保留；“恢复每日主力”取消手动选择。切换只取消该品种原未触发方案并重载该合约数据，其他品种继续运行。

## Wind 时间标签：实盘核实的重要区别

本机实测，Wind 原生 **09:35的5分钟线包含09:35这一分钟的成交**。对照1分钟序列，首根09:35线包含09:30至09:35的数据，下一根09:40线包含09:36至09:40的数据。因此标签09:35不代表09:35:00已经完整结束。

实现保留原生 OHLCV 和标签，不自行重聚合。常规K线在 **标签时间 + 1分钟 + 5秒缓冲** 后才可计算；各交易小节终点按实际休息/收盘时间截断，再加5秒：包括商品02:30、10:15、11:30、15:00，以及国债11:30、15:15。这来自2026-11-10本机实测；Wind版本或数据源变化后应重新核验。

每分钟第5秒起仍查询5/15分钟原生线的近45分钟重叠区间，保留原来的收盘确认与数据修订检测频率。辅助1分钟缓存在无人查看时至少间隔300秒、在下一轮分钟调度补查近45分钟；打开1分钟图会立即补查，查看期间恢复每分钟刷新。前端每30秒续期一次查看状态，90秒没有续期后恢复后台频率，多个页面共享同一份请求，不各自调用Wind。行情订阅与盘中预览继续实时更新，正式信号不使用1分钟缓存。

请求开头可能被截断的聚合区间、尚未完整形成的数据仍被过滤。首次打开长期未查看的1分钟图时，缓存补查期间可能短暂显示旧的完整线和最新局部预览，补查完成后自动补齐；不会用预览替代正式数据。

时间均为上海时间。首根15分钟线完成前，背景来自上一交易日最后完整15分钟线。行情时间与服务时间分别显示。零价、旧日期、交易中行情超过15秒未更新、缺失关键K线或断线都会暂停新的正式提醒。

## 规则与参数

完整策略定义、有效/失效条件、实现边界和人机分工见 [交易机会系统逻辑与人机分工](docs/TRADING_LOGIC.md)，可作为其他 AI 的接手说明。

可调门槛在 config.json，重启生效。事件保留规则版本与配置哈希，改变规则时应同步修改 version。

- 背景：EMA20、Wilder ATR14、10根效率比；趋势效率比至少0.35，震荡不高于0.25；EMA最近3根相对ATR斜率门槛0.1，其余为过渡。
- 内部枢轴左右各2根，波段枢轴各5根；严格极值确认。EQH/EQL容差取1个最小价位与0.1 ATR中的较大者。
- 顺势：同向突破实体至少60%，收盘在方向侧四分之一区域；6根内回踩冻结关键位 ±0.2 ATR，并出现实体至少50%的同向强K线。
- 假突破：震荡环境、20根区间外侧20%的关键位；从区间内越过至少1个最小价位，2根内收回，再下一根出现同向强跟随。
- 候选冻结关键位、ATR容差和区间。最小价位、价格小数位、交易日历和时段按下表及 config.json 中的 instruments 设置。
- 确认后3根完整5分钟K线未实时触价即过期，未触发方案不跨交易日（跨午夜夜盘仍属于同一交易日）；结构失效实时取消。
- v1.3要求T1为结构目标且至少1.5R才发正式提醒；缺少结构T1时保留R倍数测算并过滤，不以测算目标通过空间门槛。确认后环境改变取消待触发机会，filtered不再占用新候选名额。R未扣费用、滑点，不计算仓位。

这是独立实现的可复核规则，没有逐行复制 LuxAlgo。测试验证实现行为和时间因果性；初始参数尚未证明盈利优势，不输出未经检验的胜率。

## 历史回放与实际发布记录

页面底部“历史回放”支持选交易日期、逐根、时间轴及播放，商品包含归属该交易日的完整夜盘（例如周五夜盘/周六凌晨属于周一）。回放期间确认声音暂停。

- **历史回放**使用缓存中的最终修订K线和当前规则重算，确认时间是推算的最早可用时间，不是当时实际数据到达时间。
- **事件记录**保存当时发出的预警、确认与状态变化，包括来源K线、生成时间、关键位确认时间、规则哈希。修订追加新记录，不覆盖原提醒。

命令行导出带行情 SHA-256 的回放报告：

```powershell
.\.venv\Scripts\python.exe -m app.replay --contract IM2612.CFE --day 2026-11-09
```

默认在 reports 生成唯一命名JSON，不覆盖旧报告。没有缓存的交易日需先采集；回放不会偷偷下载更多历史。

## 全页机会氛围

页面按全部监测品种的当前有效机会显示背景：关注中为橙色流动光晕；收盘确认待触发或已触价为红色，红色优先；没有有效机会时恢复原深色。背景流动光晕、屏幕边缘呼吸光与雷达脉冲强调阶段，对应品种卡片同步高亮；顶部显示阶段、涉及品种和数量，颜色表示机会阶段，不表示多空方向或已成交。当前交易日仍有效的初始化关注也会亮橙色，保留“历史 · 静默”标签，不补发声音；历史确认、跨交易日、失效、过期、空间不足的机会不触发灯效；断线、离线回放、品种休市或数据未就绪时不作为实时提醒。

页底“预览橙色关注 / 预览红色确认”只演示灯效，不生成机会或修改数据；明确显示预览标记，30秒后自动恢复，也可点击“恢复实时”。系统设置减少动态效果时，保留静态配色并停止动画。前端更新后重新构建并刷新页面，不需要为灯效重启Wind采集。

## 期权增强：环境与交易工具比较

在品种卡下方查看“期权环境”，点“期权链与研究”打开盘口、IV曲线、持仓分布和验证记录。图表下方的“交易工具比较”只关联当前交易日的已确认/已触价期货机会；没有合格信号、盘口或期限时显示原因。原期货提醒保持原规则，期权报价与IV变化不会重复响铃。

| 期货 | 期权覆盖 | 定价口径 |
| --- | --- | --- |
| IM / IF / IH | MO / IO / HO，对应000852.SH / 000300.SH / 000016.SH指数 | 欧式Black-76，按同到期日同步认购认沽平价估算远期 |
| AG / AU / SC | 只接受当前选择的真实期货月份期权 | 美式Barone–Adesi–Whaley，期货持有成本b=0 |
| T / TL | 无已验证覆盖 | 继续原期货监控 |

每次确认冻结日内、1/3/5交易日的工具候选和原始输入。每个持有期取最近两个合格到期日，至少剩余`max(5,持有期+2)`个交易日；商品同月份只有一个到期日时如实显示，不借用其他月份补齐。单买按绝对Delta接近0.5挑选；支付权利金价差的卖出腿位于T1方向，收取权利金价差的卖出腿在结构失效位外，并有更外侧买入保护腿。缺腿则不提供该方案。

期权与期货均按各自一手列示参考情景，**并非相同风险预算或仓位建议**。期权买入看卖价、卖出看买价，持有期退出估计为模型价加减当前半价差；另计每腿每次1个最小价位的压力滑点。情景为当日收盘及第1/3/5个交易日收盘，IV相对下降20%、不变、相对上升20%，不是预测区间。期货止损情景不保证能以该价成交。

指数行权价不是期货价格。选择结构腿时把期货关键价按当前“指数−期货”差额换算；估值情景将同样的期货价格变化加到该到期日的隐含远期，保持期现差与期限差。这是假设，不能覆盖基差突然变化。到期收益图的横轴是期权标的价格，与持有期图的期货价格情景分开。

美式价差的到期损失上限以完整组合为条件，提前行权可能形成期货头寸。模型保留版本和输入，不能保证美式估值精度或两腿同时成交。所有Greeks按远期口径计算；组合Delta/Gamma乘了合约乘数，Vega为IV变化1个百分点的金额，Theta为1个日历日的估值变化。

### 费用与参数

期权参数集中在`options-config.json`，与原期货规则版本分开。默认年化利率2%是可配置假设，不是实时无风险利率。修改文件后重启生效。

- 详情页底部可保存该品种“元/手/单边”期权手续费，含交易所及券商费用。留空表示未知，填0表示明确按零估算；默认全部为空。
- 页面保存的费用覆盖保存在SQLite，优先于文件中的该品种期权费率；既有冻结研究记录保留确认时的参数。
- 期货费用通过`futures_fee_per_contract_each_side`配置，同样默认未知。当前费率采用单边固定金额估算；平今/平昨或比例费率应按交易场景折算并在复核时校正。
- 手续费未知的方案只显示“未扣手续费”，不称为扣费优势。定价、滑点和手续费不同口径不能混算。

### 数据更新与留痕

独立Wind进程内串行请求，期货任务优先；期权链和盘口查询分批，至多一个期权请求在途。当前监测池每个到期日取距离现价最近的21个行权价，默认30秒刷新。交易中的完整监测池及仍在观察的候选腿作增量实时订阅；集合变化时保留未受影响的订阅组。持仓图仅表示监测池，不能推断全部市场持仓、做市商净方向或有正负号的GEX。

30秒为快照入队周期，不保证每批都在30秒内完成。Windows每批上限由`quote_batch_size`控制（默认60），Mac另受`mac_quote_batch_size`限制（默认8），以减少单次原生调用长时间阻塞；快照仍只允许一个请求在途，期货请求保持优先。AG/AU/SC期权使用同月份期货的实时标的报价，指数期权继续使用指数报价。
`GET /api/state`的`acquisition`提供当前等待/执行请求、期权队列、原生调用耗时统计和报价处理延迟；控制响应与行情分队列传送，避免请求完成消息被大量行情阻塞。超时事件记录具体操作、品种与执行秒数。重连不一定是官方应用崩溃，先核对该记录及系统崩溃日志。相关修复和验证边界见`reports/options-commodity-feed-fix-2026-11-10.md`。

SSE每秒推送盘口及环境摘要，新的环境版本会驱动候选和详情重新读取，5秒轮询作为补充。页面可见时记录行情收到至下一帧的延迟，重载/恢复的第一包不计为新行情延迟。2秒是待盘中验证的目标。

盘口要求双边正价、未交叉、至少各1手、相对价差不超过20%，行情不超过15秒，标的/期权及组合各腿时间差不超过10秒。成交量为0但盘口合格可以使用。完整快照初始化后的连续增量回调保留未变化的盘口字段；字段最后变化时间不等于停止更新。断线会清除初始化状态，旧行情时间、缺失/无效盘口仍会被拒绝。盘前、午休、收盘、断线、期货尚未同步时不产生候选。收盘后Wind可能继续更新某些行情时间，而指数时间不变；不同步时IV显示缺失，不能放宽成可交易报价。

RV5/RV20只用同一标的、完整连续交易日的日收盘对数收益，年化因子√252；当日未完成日线不纳入。15分钟IV变化需同到期日、15–16分钟前的有效采样，跨休市缺口不拼接。Wind `us_impliedvol/delta/gamma`目前按上一交易日日终取样核对，不能与盘中中价模型当成同口径误差。`RT_OI`自身更新频率尚待盘中核验，行情时间不能充当持仓统计时间。

排障时可在启动服务的环境中设置 `WIND_DESK_OPTIONS_DISABLED=1`，临时停用期权请求和计算，保留期货采集；删除该变量并重启即可恢复，不修改共享配置。只运行一个采集服务。用 `scripts/observe_stability.py --mode futures-only|options-on --seconds 600 --output reports/本机测试.json` 记录直连本机API的对照数据（把模式替换为其中一个值）；脚本等待历史同步完成后计时，期权模式还要求交易中各品种至少有一份有效估值。

普通期权权限/查询失败只暂停期权部分。由于同用一个Wind原生进程，若原生调用本身卡死到超时，仍需重启该行情进程并静默补数，不能承诺期货完全无停顿。

SQLite `option_records`追加存储链、盘口、环境、信号原始输入、比较方案、生命周期、触价、报价路径和评估；历史回放不生成实时研究信号。触价时记录实际观察价格及当时盘口，而非把理想触发价当成交。逐笔接收的期货报价更新有利/不利极值，期权报价路径每分钟采样；断线空白不补造。第0/1/3/5日收盘前10秒尝试记录评估，未取得对应盘口就记录缺失；跨日研究不会延长原日内交易信号。

“验证记录”保留全部基准信号，并按品种、模型、持有期、IV/RV及IV扩张状态分组显示描述性结果。至少20个有信号的交易日只是首轮检查起点，不代表统计有效。缺费、缺盘口、未触价或样本不足的情况单独记录。

期权API：`GET /api/options/context`、`/chain`、`/candidates`（均支持`root`）；候选支持`holding_days=0/1/3/5`；`GET /api/options/research`、`/settings`、`/audit?kind=signal|comparison|evaluation|path&root=IM`；`POST /api/options/fees`接受`{"root":"IM","fee":null}`。审计接口只读，不会重新计算后覆盖旧记录。

## 安装与维护

### macOS

Mac 需要从 Mac App Store 安装官方 **Wind API** 应用（与 Wind 金融终端是两个应用）。
官方 Python 模块位于 `/Applications/Wind API.app/Contents/python/WindPy.py`，
它加载同一应用包中的原生动态库；不要仅从第三方包源安装同名模块。

安装 Python 3.12 和 Node.js 后，运行 `./install-mac.command`，或在 Finder 中双击它。
两端安装器共用 `scripts/configure_wind.py`，仅为本项目 `.venv` 写入 `WindPy.pth`，不修改系统 Python。
SDK 目录优先使用 `--wind-python-dir` 参数或 `WIND_PYTHON_DIR` 环境变量，其次保留已有有效配置，最后尝试系统默认路径。
可用 `.venv/bin/python scripts/configure_wind.py --check` 只检查路径（不等于验证连接）。
运行 `.venv/bin/python wind_check.py` 验证接口；首次调用可能弹出独立的 Wind 登录框，
需用自己的 Wind 账号登录。终端已登录不代表 Python 接口已完成认证。
若每次新进程都要求登录，可自行在官方登录框选择自动登录；现有服务连接超过25秒会重启行情进程，
因此首次人工认证建议先通过上述独立检查完成。若看板仍持续显示“正在连接 Wind”，需检查它新弹出的登录框。

双击 **Start Dashboard Mac.command** 后访问 `http://127.0.0.1:8765`。
保持终端窗口打开，按 Control+C 停止服务。Windows 启停脚本不适用于 macOS。
在受限执行环境中，原生 SDK 需要访问用户目录（例如 `~/.Wind`）和网络；
若加载成功后原生进程退出，应在普通终端运行连接检查以区分权限限制与 SDK 问题。

### Windows

每台新电脑都需要安装并构建。需要64位Python 3.12、Node.js（Windows原验证版本24，Mac本机25）、Wind终端及Python API权限：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

安装使用 requirements-lock.txt 和 frontend/package-lock.json。WindPy引用保存在本机 `.venv/Lib/site-packages/WindPy.pth`，默认查找当前用户的：

```text
%USERPROFILE%\Wind\Wind.NET.Client\WindNET\x64
```

Wind安装位置变化时设置 `WIND_PYTHON_DIR` 并重跑安装器，或调用共享配置脚本；不要提交本机 `.pth`。基础连接检查保留：

```powershell
.\.venv\Scripts\python.exe .\wind_check.py
```

行情和审计库：data/desk.sqlite3（SQLite WAL）；日志：logs；启动器记录：data/server.pid。数据留在本机，没有自动清理；长期运行需留意磁盘占用。备份应停止服务后复制数据库及仍存在的WAL文件，或使用SQLite backup API。

## 刷新负载与验证（2026-11-12）

期货实时订阅和5秒快照保持不变。期权仍订阅交易中的完整监测池，每30秒检查补数需求；只有同交易日完整盘口初始化、订阅回调持续更新且报价合格的合约，才跳过重复快照，并每120秒完整审计。未初始化、过期、异常盘口继续30秒补查；重连清空初始化和快照记录。15秒新鲜度、10秒同步、20%价差和挂单量门槛不变。Mac每批最多8个、Windows最多60个。

降幅取决于活动方案和期权盘口质量，不是每个品种固定省同样数量。`acquisition.native_requests.bars.by_timeframe` 可分周期观察实际请求次数；初始化请求也计入，应取稳定运行区间的计数差。两个平台共用此逻辑，Windows真实SDK仍需另行盘中复验。


Mac期权补快照使用官方 `wsq(..., func=...)` 注册临时回调，收到本轮完整字段后取消临时请求；等待期限10秒、在工作线程下一轮调度清理，缺失代码记入期权研究指标 `snapshot_timeouts` / `last_snapshot_timeout`，不凭空补数据。等待回调不占原生请求队列；注册、取消和其他原生调用仍受45秒保护。Windows保留现有同步快照路径，须在实机验证后再决定是否切换。`acquisition.pending.waiting_callback` 区分回调等待与原生执行，Mac快照 `native_seconds` 统计注册和取消耗时，不含等待行情的时间。

只读观察可用 `scripts/observe_stability.py --mode options-on --seconds 900 --output reports/新的文件名.json`。默认检查全部交易中覆盖品种；若匹配月份期权已经到期，可明确指定 `--roots AG AU` 限定连续估值验收范围，原始采样仍保留其他交易中品种的状态，报告标出被排除品种。不能用此参数隐藏未解释的数据故障。

本轮失败复现、回调修复、15分钟连续验证及边界见 [刷新压力与灯效报告](reports/refresh-pressure-and-atmosphere-2026-11-12.md)。
