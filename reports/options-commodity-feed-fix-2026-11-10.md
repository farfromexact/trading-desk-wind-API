# Wind重连与商品期权行情修复

日期：2026-11-10，上海时间。Mac arm64、Python 3.12、官方Wind API 26.1.7。只运行一个Wind采集子进程；观察脚本绕过代理，直连本机HTTP，不另开SDK连接。

## 已定位的问题

1. 商品期权估值曾使用期权模块缓存的旧标的快照，覆盖期货模块同一真实月份合约的最新报价。21:23的保存状态中，旧来源使SC为0/42有效，改用同期货报价后同一份输入可得到7/42。指数期权仍需独立指数报价。
2. Wind实时订阅是增量更新。完整盘口初始化后，未变化字段的最后变化时间被当作最后更新时间，造成盘口仍在持续更新时误判不完整；此外旧实现只订阅部分合约，其余依赖慢速轮询。
3. 请求完成消息与大量行情共享队列，处理行情时又反复计算交易日/已完成K线边界。改为控制与行情分队列、有限时行情消费，并缓存同秒内相同日历的完成边界。期货逐笔顺序保留，不合并价格触碰。
4. 原有全局期权订阅集合变化会取消重订，积压的过时集合进一步增加调用。现在仅保留最新待处理集合，保留未受影响的订阅组，交易中订阅完整监测池。

21:44:17和21:49:28均记录到 `option_snapshot` 超过45秒后的看板主动重启。只把Mac批量缩为8，仍出现过超时，不能把小批量单独称为解决方案。旧日志没有原生完成耗时，不能回溯证明每次超时都来自队列拥堵；新增诊断用于区分原生调用耗时与报价处理延迟。

检查期间官方Wind主程序持续存在。仅找到19:28的Python SIGABRT报告，位于初次受限环境的GUI注册；没有证据证明之后每次界面消失都是官方Wind主程序崩溃。经授权的手动重启与自动重连分别记录。

## 最终实现

- AG/AU/SC复用同月份期货实时报价；没有报价就保持缺失，不以旧缓存回填。冻结研究输入继续深拷贝。
- 完整快照初始化当前交易日盘口后，连续增量回调可以确认未变化字段。断线清除初始化状态；显式无效字段、过期/超前行情、宽价差、无挂单量仍拒绝。15秒新鲜度、10秒同步、20%相对价差保持不变。
- 期权请求至多一个在途，期货排队优先，初始历史同步优先；增量分钟线刷新不再完全阻断期权排队。快照合并待处理批次，优先近价行权价；Windows上限60，Mac上限8。30秒是入队间隔，不是完成时间保证。
- `acquisition`提供当前请求操作/品种/运行时长、原生调用计数和最大耗时、报价接收到处理延迟、期权待处理队列。原25秒连接与45秒请求超时不变。
- 清理重启时的进程队列，退出路径确保关闭存储；Mac启动器给现有SSE连接5秒退出期限，避免停止服务一直等待浏览器长连接。
- 新增 `WIND_DESK_OPTIONS_DISABLED=1` 临时诊断开关、只读 `scripts/observe_stability.py`，支持Windows和Mac。未修改Windows启停实现或依赖；不提交SDK、本机登录和原始行情记录。
