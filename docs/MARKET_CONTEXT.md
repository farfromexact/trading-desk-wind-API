# 盘面底色：WindPy 数据与口径

## 当前实现（2026-11-16）

Windows/macOS 共用同一个 `WindPyContextClient`。所有正式行情、期权及盘面底色查询均通过已经登录的 **WindPy**。不调用 MCP、Node CLI，不读取 API Key，不配置 `WIND_CONTEXT_CLI` 或 `WIND_CONTEXT_FUND_CLI`，也不会失败后转去 MCP。Node 仅用于前端构建。

`app/market_context.py` 管理只读背景缓存与调度；`app/wind_context_client.py` 校验 WindPy 返回的字段、代码、日期并转换格式；`app/context_wind.py` 在原有唯一 WindPy worker 中执行请求。主行情与期权优先级高于背景查询，后台单在途，排队超过15秒让行。仅Windows背景WSQ与现有主行情一样采用同步快照，由同一工作线程串行调用并受原生看门狗保护；Mac的注册、回调处理和取消逻辑保留原样，10秒未完整返回则报缺失。完整字段必须来自同一回调，不使用注册返回值中的数据，也不把零散增量拼成完整快照。

背景字段/权限错误只显示在面板，不进入主行情重试队列。单次原生调用超过2秒后，背景查询暂缓60秒；连接失败时取消后台等待，暂缓5分钟。原生调用仍受原有45秒看门狗保护，连接25秒保护不变。低优先级不意味着可以抢占已经执行的SDK同步调用，须在Windows及盘中继续观察延迟。

正式5/15分钟信号、交易日归属、行情新鲜度、完整性、期权模型、声音规则保持原样。背景读数不输入交易引擎。

## 使用与刷新

- 首次默认按需查询，点击“刷新”运行一轮；“盘中更新”开启股指交易时段每30秒检查，开关保存在本机 `data/market-context-settings.json`，重启后恢复上次选择（离线/禁用时不查询）。页面每3秒读取本机缓存；更多浏览器页面只读同一缓存，不各自查询Wind。
- `/api/market-context` 读取本机缓存。POST `/refresh` 与 `/monitor` 控制盘面底色。图左的ETF监测在交易时段独立运行。POST `/audit` 通过同一采集器核验四只固定ETF，与刷新互斥，冷却60秒。
- `WIND_DESK_CONTEXT_DISABLED=1` 或离线模式禁止上述查询。
- 五组广度按需或每30秒读取一批，完整5分钟线按新标签更新，跨市场每5分钟一批。四只ETF的资金流盘中每15秒合并一批。估算净申赎成功后每日一次，失败后30分钟重试。
- 历史成交基准每轮最多补一只指数此前20个交易日，复用完整缓存，至少10个有效同刻样本才计算。首次三只指数基准需要多轮刷新。所有调用串行；实际调用数、耗时可查看 `/api/state` 的 `acquisition.native_requests.context`。

## 指标与单位

| 项目 | WindPy 与计算规则 |
| --- | --- |
| 三指数与两板块上涨广度 | 上证50 / 沪深300 / 中证1000 / 科创板 / 创业板；WSQ `rt_up_total,rt_down_total,rt_same_total,rt_date,rt_time` 同批。上涨÷（上涨+下跌），排除平盘；前三指数非负整数家数须合计50/300/1000；后两板块按用户最终选择直接展示Wind聚合返回的有效家数，数量为动态范围，不宣称已独立核验全板覆盖，不订阅成分股 |
| 相对强弱 · 5m | 中证1000减沪深300的最近完整5分钟收益率，单位百分点；两端都须有同步、连续的两个5分钟收盘价，不跨午休 |
| 成交偏向 · 5m | 当期（中证1000成交额/沪深300成交额）÷此前20日同刻配对比值的中位数，至少10个有效配对日期。>1更偏小盘成交，<1更偏大盘；当前1000零成交可为0，300零成交不可做分母，历史比值须正数 |
| 广度差 | 当前中证1000上涨占比减沪深300，单位百分点；双方源时间须同交易时段、相差≤10秒。另列其近5分钟变化，历史对照双方也须相差≤10秒 |
| 成交活跃度 | `WSI close,amt; BarSize=5`；原生amt可能返回字段名AMOUNT，金额元。三个完整5分钟成交额之和 / 此前20个有数据交易日同刻中位数，至少10日，不跨午休 |
| 期货位置 | 复用已有期货报价与已确认结构。已连接且已收盘时显示“已收盘”，盘中未就绪或断线时显示“等待行情”，不放松实时条件 |
| 跨市场 | 仅已监测真实合约AG/AU/SC/T/TL；保留各自日期、时间。WSQ RT_PCT_CHG小数比例转换为百分数，RT_AMT为元，不推定净流入或资金轮动 |

完整5分钟线在标签后65秒采用。原有IM/IF/IH成交活跃度继续使用15分钟窗口；右侧风格观察使用5分钟，1000/300基准替代旧1000/50。分钟线终态历史不等于当时已经收到的数据，不能回填为当时可交易信号。

## ETF：必须区分两个口径

监测四只代表产品，分别为512100.SH（南方中证1000ETF）、510300.SH（华泰柏瑞沪深300ETF）、159915.SZ（易方达创业板ETF）和588000.SH（华夏科创50ETF）。

- **今日累计与流速**使用 WindPy `WSQ` 同批返回的 `rt_date,rt_time,rt_insti_buy_amt,rt_insti_sell_amt,rt_vip_buy_amt,rt_vip_sell_amt`，请求 `unit=1`。累计净额为超大单与大单买额减卖额。每只基金按自己的行情源时钟计算近5分钟净额变化除以实际经过的分钟数。匹配目标时刻及之前75秒内最近的有效快照，午间和隔夜分别起算。休市期间保留最后时点。多个页面共用唯一低优先级采集器。
- **20日同刻**以交易日历中的前20个交易日为样本，分别计算累计净额均值、平均净流速和今日累计相对均值的有符号差额。缺少部分时点时按实际天数展示累计差额和均值，标明有效样本数。启动时从本机已存的 WindPy 日内回执恢复历史。2026-11-19 实测，在 510300.SH 上用 WSI 查询历史 1 分钟的 `mfd_inflow_m`、大单买卖额及其 `rt_` 字段均返回无效指标（-40522006）。
- **较滚动20日均额**用今日累计减去同一快照的 `rt_mf_amt_20d ÷ 20`。该窗口含今天截至快照时刻的净额，分母固定为20个交易日。正负净额和真实零值均保留。即使本机没有往日同刻样本，这项差额也可计算。当前 WSQ 批次只增加 `rt_mf_amt_20d` 一个字段。旧回执或该字段缺值时，滚动指标留空。若 Wind 拒绝扩展字段，采集器以原字段继续采集，并在30分钟后再尝试滚动指标。
- **20日全日均值**取 WindPy `WSD MFD_INFLOW_M` 的20个完整交易日算术均值，按代码与实际返回日期校验后缓存。相同交易日的日频值与盘中口径收盘值实测有差异，例如 11 月 18 日 510300.SH 分别为 −786.47 万元和 −5.70 亿元。全日均值仅单列参考，同刻比较始终使用盘中快照。
- 启动时只保留 `source=WindPy WSQ` 且 `frequency=intraday_cumulative` 的资金流缓存，旧WSD/MCP金额不放入新日内行；其他背景和净申赎缓存保留。查询失败不回退WSD/MCP，不补零，不改主行情门槛；旧的有效WSQ快照保留原时间，页面显示滞后/历史。
- **估算净申赎**：本轮 `F_MF_NETSUBAMT` 的WSD请求以及含日期字段的WSS请求均被拒绝，尚未验证可用的直接金额字段。正式实现用每只ETF上一完整交易日与前一交易日的 `WSD UNIT_TOTAL,NAV;unit=1;Fill=Blank`，验证实际返回日期后计算“份额净变化×当日单位净值”。页面明确标记**估算**，不是原MCP金额字段或逐笔现金到账。
- 资金流面板按量级显示万元或亿元，流速单位为万元/分。缺失保持空值，0 表示已取得的零值。份额净申赎单列，份额或净值缺失、日期不匹配或非正数时保留缺失。
- 显式POST `/api/market-context/audit` 通过同一采集器检查当前WSQ字段和行情时间，再用上一完整交易日的WSD/WSS份额与净值交叉核对。四只ETF共7个串行请求。实际字段覆盖、单位缩放与终端金额对照分别记录。

## 本机缓存与交接

收盘后收到带当日 Wind 源时间的 ETF 快照时，仍可用有效的累计净额和滚动总额显示滚动 20 日均额与差额。近 5 分钟流速和往日同刻对照继续使用交易时段的样本。

新缓存 `data/market-context-windpy.json`；原始回执 `data/market-context-windpy-observed-YYYYMMDD.jsonl`；ETF审计 `data/market-context-windpy-etf-audit.json`，解析前原始回执 `data/windpy-context-raw-YYYYMMDD.jsonl`。均已被Git忽略，不保存凭据。

旧 `market-context.json` 不会被正式服务加载或覆盖，避免来源变化时旧资金流冒充新数据。离线历史预览脚本仍可读取明确提供的旧研究回执，不访问MCP网络。11月14日的MCP验收仅为历史记录，不代表本次WindPy验证。

本轮实际结果及尚未验证项见 `reports/market-context-windpy-2026-11-16.md`。Windows接手应重新构建前端、重启本机服务，然后核验真实SDK权限和盘中延迟；Mac测试不能代替Windows实机验收。

## 五组广度与近5分钟变化（2026-11-16追加）

广度从3×5扩成5×5字段，每次增加10个标量，仍一轮一个WSQ注册/取消；5个代码合并查询，未新增成分股订阅。科创板、创业板只查聚合广度，不查分钟线、历史成交额或对应ETF。右侧复用原IM/IF的WSI缓存与原有20日历史补齐，没有额外原生查询；盘中仍最多每30秒刷新，5分钟变化窗口不等于每5秒调用API。

广度变化目标为当前源时间减5分钟：选目标之前90秒内最近一条，禁止目标之后、跨午休、跨日或缺失值替代。源时间相同的收盘快照只覆盖同一个缓存点，不会积累出虚假变化。卡片趋势线显示近30分钟源快照，0—100%固定纵轴；相邻超过90秒或无效值则断开，少于两个连续样本显示待积累。

界面用红/绿显示上涨广度相对50%的位置，用紫/蓝表示偏小盘/大盘，避免将风格方向误认成涨跌或交易机会。每项显示自己的数据时间和滞后状态，不把旧现货数据当成夜盘实时数据。当前广度差与5分钟变化分开标记，不把“当前差值”冒充“5分钟变化”。所有观察均不输入正式信号。

Windows/macOS共用；需构建前端并重启。真实验证见 `reports/five-index-context-2026-11-16.md`，旧迁移报告保留当时结果。


按用户最终选择，五张卡是**三指数＋两组Wind板块聚合**。实测000688.SH返回619家、399006.SZ返回1370家，不按科创50/创业板指的50/100样本解释。UI显示“科创板 / 创业板 · Wind聚合”与实际返回总家数；`coverage=vendor_reported`、`scope_ok=null`，不能把这些数值写成已独立核验全板或逐只复算涨跌。负数、非整数、缺失家数或涨跌合计为0仍拒绝计算。前三指数的50/300/1000数量校验保持不变。

本轮曾尝试名单核验，空返回后的一次全A名单WSET触发Mac原生45秒超时及一次重连；**名单路径已移除，背景执行器不允许WSET，不会重试该查询**。最终只增加同一WSQ批次里的两个代码（共10个标量）；不查名单、不查个股行情、不新增持续订阅，也不改原生超时保护。详见验证报告中的失败记录与最终观察，不能把整轮工作称为零重连。

## 指标说明按钮

指标旁的“?”支持悬停、键盘聚焦和点击固定说明；Esc、再次点击或点击空白处关闭。说明包含广度分母、pp与涨跌幅区别、近5分钟历史积累、相对强弱/成交偏向/广度差公式、15分钟活跃度、期货位置和ETF口径。浮层放在页面最外层并约束在视窗内，避免被卡片裁切；不触发刷新或Wind请求。
