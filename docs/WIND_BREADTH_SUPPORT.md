# 给Wind技术支持：中证1000实时涨跌家数的WindPy查询

> 此文前半保留最初技术支持问题。当前字段已由用户提供并在Mac实测；最新实现见文末与 `docs/MARKET_CONTEXT.md`。

## 最初需要解决的问题

现有本机看板已通过登录的官方WindPy查询期货、期权、指数分钟线和ETF。Windows/macOS共用代码；Mac使用Wind API 26.1.7、Python 3.12 arm64。现在仅缺中证1000（000852.SH）当前成分股的实时聚合涨跌家数。

计算：小票参与度 = 上涨家数 /（上涨家数 + 下跌家数）×100%。另展示该比例与15分钟前的百分点差。不是指数涨跌幅，不是全市场涨跌家数，也不是小盘ETF资金流。

## 请提供

1. **可执行的WindPy示例**：查询000852.SH的上涨、下跌、平盘家数，以及源交易日期和行情时间。请给出准确的函数、英文指标代码、全部必要参数和一份真实返回示例（ErrorCode、Codes、Fields、Times、Data）。仅有中文界面指标名无法接入。
2. **取数方式**：现有客户端WindPy的WSQ/WSS/WSET是否支持服务端聚合？是否能订阅，或每60秒查询一次？Windows和macOS是否均可用？不使用Alice、MCP、HTTP API Key或另一个DataFeed SDK。
3. **统计口径**：涨跌是相对前收盘还是其他基准？停牌、无成交、缺报价、除权成分分别如何处理？上涨+下跌+平盘是否覆盖全部当前成分；如不覆盖，能否返回有效/缺失/停牌及总家数，供完整性校验？
4. **时间和权限**：更新频率、是否有延迟、源时间如何取得；我的账号需要什么现有/额外权限？Mac最低SDK版本是什么？
5. **若无聚合接口**：请明确说明，并推荐只使用现有WindPy、低压力获取同口径广度的方式及批量/频率限制。不要默认新增1000只股票的持续订阅。

最有用的交付是：一段能够直接执行的Python代码、一次实际返回、指标定义和权限说明。请不要发送账号密码、许可证或API Key。

## 当前实现约束

仅一个WindPy worker，期货和期权请求优先，背景查询低优先级且单在途。不另外启动Wind登录，不改变原5/15分钟信号、行情新鲜度或完整性门槛。字段尚未确认时明确显示缺失，不补零、不用过时数据标成实时。

Wind技术支持确认定义后，先以000852.SH单次只读请求核对，再接入每60秒背景刷新；只有拿到可靠的源时间与完整覆盖信息后才恢复15分钟参与度变化。

## 用户后续提供的字段

用户提供：`w.wsq("000852.SH,000300.SH,000016.SH,000688.SH,399006.SZ", "rt_up_total,rt_down_total,rt_same_total")`。

实现仅沿用面板现有三指数，加入`rt_date,rt_time`，维持同一请求和完整覆盖校验；暂不新增科创板/创业板功能。此代码已解决字段映射信息缺口，实际原生验收及停牌口径边界见迁移报告最新补充。


## 当前结果与仍可向Wind确认的问题

11月16日已使用用户提供的五代码WSQ和源时钟。前三指数数量匹配；000688.SH实际返回619家、399006.SZ返回1370家，用户选择后两张显示科创板/创业板的板块广度，不按科创50/创业板指样本解释。用户最终选择直接使用Wind聚合返回，不再核验名单；没有逐只查询或订阅股票行情。两板块标为Wind聚合口径，不宣称独立完整覆盖。

当前变化窗口按用户要求改为近5分钟，不再是15分钟。仍可请Wind书面确认：后两个代码的rt_up_total统计范围、停牌/无成交处理、源时间定义、WSET板块名单是否与WSQ统计池始终一致；ETF MFD_INFLOW_M的unit参数为何不缩放。无需再索取已确认的聚合字段代码。
